*Reviewed: 2026-08-15 | Languages: Python, JavaScript/JSX, LaTeX | Depth: full | Paper: `最终版report.tex`*

## Overall Assessment

The project-internal evidence chain is strong after the corrections applied during this review: the core tensor contract, method stages, frozen final split, eight-method results, primary and supplementary statistics, LAMM comparison, post-hoc diagnostics, release manifests, and browser bundle can all be traced to current repository evidence. The final TeX was read in full (4,469 lines), 140 code files were reviewed (about 43,297 lines), 537 repository text/evidence files were indexed, all 23 tables and 40 included image assets were inventoried, and the rebuilt 81-page PDF was visually inspected page by page.

The Report cannot yet be described as independently reproducible from a clean public checkout in the strongest sense. The supplied directory has no `.git`, licensed FaceScape data and exact private checkpoints are unavailable, there is no single portable full-GPU `run-all` pipeline, the browser verifier compares selected outputs and aggregates with stored goldens rather than launching a live Python reference, and the exact final composite figure files used by the TeX are not committed in this repository. The Report has been edited so that it no longer overstates these boundaries.

- The release verifier checks all eight manifest-listed browser artifacts. After this review it also checks the two previously unverified core golden hashes, computes the actual new-fold count, and fails closed at the common adapter boundary.
- Source snapshots, evidence roots, SHA-256 sidecars, seed/resume state, and current-versus-historical source isolation are unusually well documented.

## Applied Evidence-Backed Corrections

### Report corrections

1. **Final confirmation split corrected.** The prior text conflated the parent 676/70/100 PCA-stratified split with the final confirmation split. The Report now states: 846 valid parent identities; 100 previously observed parent-test identities excluded; final 576/70/100 split; `split_seed=20260809`; ascending SHA-256 order; 64-D source PCA fit on 576 training identities. Controlling evidence: `results/rbsr_final_rerun_holdout_v1/protocol/final_rerun_holdout_split_manifest.json`, `FINAL_RERUN_HOLDOUT_POLICY_FREEZE.json`, and base metadata.

2. **Holm families and primary p-values corrected.** The frozen primary family is certified RB-SR versus matched Ridge across six metrics, not the 42-test all-method family. The Report now uses the six-family adjusted values: ROI RMSE about `5.5e-13`, new flips about `2.3e-17`, and edge strain `0.198`. The 42 comparisons are labelled secondary.

3. **Runtime admission logic corrected.** Only control applicability `chi` retains, scales, or withholds a request. Browser normal flips and edge strain are descriptive read-outs; the Ridge-relative certificate controls learned-residual admission. Claims that edge strain itself shrinks or rejects an edit were removed.

4. **Display and evaluation frames separated consistently.** The Report already explained the display transforms; a later contradictory promise that consultation geometry was identical to benchmark geometry was removed. Browser checks are now described as selected comparisons with stored reference goldens.

5. **Replay scope narrowed to the implemented scope.** `tools.reproduce replay` does not recompute every statistic in the dissertation. The Report now states that it replays the primary six-metric and supplementary three-metric analyses, while other tables/ablations remain traceable to separate committed records.

6. **Unsupported compute claims removed.** The repository contains no public `implementation_constants.json` or committed evidence for the former 87.5/104 MB A100 memory figures and 7.07/7.81/8.48 ms latency quantiles. Those values and the derived interactive-latency conclusion were removed. The remaining cost table is limited to committed metadata.

7. **Conformance wording calibrated.** `independent PASS records` became executable checks; `against the reference implementation` became comparisons with stored reference goldens; claims are limited to selected outputs/aggregates.

8. **Text defects corrected.** The malformed `7,ms` expression and `I remains responsible` grammar were corrected or removed during the evidence rewrite.

9. **Incorrect bibliography DOI corrected.** `botsch2005rbf` pointed to DOI suffix `00885`, which is *Harmonic Guidance for Surface Deformation*. The official Eurographics record identifies *Real-Time Shape Editing using Radial Basis Functions* as `10.1111/j.1467-8659.2005.00886.x`; the Report now uses the correct DOI. All 51 bibliography keys are both defined and cited. Forty-five entries expose a network identifier that returned HTTP 200; the Sorkine--Alexa ARAP DOI resolves correctly at the publisher despite Crossref returning 404, and five book/conference items have no network identifier in the Report.

10. **Non-existent figure-source notes corrected.** Two non-rendered redraw-instruction arguments cited a missing `paper_rewriting_output/figure_sources/verified_spatial_reference.png`, and the framework note cited a missing `paper_rewriting_output/final_paper/figures/rbsr_overview.png`. They now point to the released topology bundle (`head_mean.json`) and the actual method implementations/component table.

11. **Browser deployment asset and service wording corrected.** The cost table named a non-existent `engine.json`; the released operator is `demo/public/bundle/ridge_browser.json`. The former absolute claim of “no server inference” was narrowed: the standalone local path needs no server, while the implementation optionally attempts a configured certified service first and then fails closed to local certification or Ridge.

## Code Quality Summary

The current public wrappers are well structured around explicit path resolution, manifest validation, isolated source materialisation, seed registries, atomic writes, and sidecar hashes. Training and evaluation implementations contain strong input-shape assertions, identity-disjointness checks, resume signatures, deterministic loader generators, and deferred-test guards.

The main maintainability weakness is orchestration rather than core numerical logic. The frozen experiment sequence is spread across provenance notebooks, stage CLIs, and result manifests. `experiments/lamm/run_lamm_facescape.py` is also a large multi-stage file, and several historical low-level entry points assume a particular cwd or Colab layout. These are not contradictions with the now-calibrated Report, but they prevent a one-command clean-room rebuild.

### Paper Summary

Rhinoform formulates nine-landmark, source-conditioned sparse-control nasal deformation on registered FaceScape geometry. It compares eight methods on a frozen identity-disjoint final confirmation protocol, proposes a Ridge-anchored CVAE residual with a learned spatial gate and hard Ridge-relative fold certificate, and translates the selected accuracy-regularity operating point into an anchor-first browser consultation prototype. The primary claim is a modest but statistically supported certified RB-SR improvement over its matched Ridge anchor; LAMM is more accurate, ARAP is more regular, and a PCA-128 post-hoc study demonstrates a different family operating point.

### Mapping Summary

- Core tensor sizes, method equations, architecture, main table, RB-SR-vs-Ridge effects, LAMM, PCA-128, ablations, noise/sub-unit outputs, and browser policy are HIGH-confidence matches.
- The original Report discrepancies were final split/seed/algorithm, primary-vs-secondary Holm attribution, replay overclaim, unsupported compute measurements, display/evaluation identity, and runtime strain gating. All were corrected in the final TeX.
- Remaining uncertainty is about clean-room reproducibility and exact artifact provenance, not about the committed headline table values or the implemented core method.
